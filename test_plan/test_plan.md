# BIRD — Test Plan

**Project:** BIRD (Birzeit Integrated Router Design) Functional Verification
**Course:** ENCS5337 — Chip Design Verification, Birzeit University
**DUT:** `bird` (instructor-provided behavioral model, `design/bird.sv`)
**Reference:** BIRD Functional Specification (`spec.tex`)
**Methodology:** Class-based SystemVerilog testbench (no UVM) — interface, transaction, sequence, driver, monitor, functional coverage, scoreboard, environment, test, top.

---

## 1. Verification approach

Stimulus is generated by `bird_sequence` and driven onto the input interface
(`in_vld`/`in_rdy` handshake) one byte per cycle (payload bytes followed by the
two CRC16 bytes), with the `cfg` sideband held stable for the fragment. The
`bird_monitor` reconstructs each input packet and samples the local and remote
output streams. The `bird_scoreboard` acts as a **spec reference model**: it
predicts the expected local/remote output and the expected drop behavior from
the spec, then compares against what the DUT produced and against `drop_cnt`.
`bird_coverage` records which input conditions were exercised.

A test **passes** when the observed output and `drop_cnt` match the spec
prediction. A **mismatch is a finding** — either a DUT defect or a point needing
review.

## 3. Findings (summary — full detail in `docs/verification_report.md`)

- **BUG‑1 (High):** Local packets with SEQ_NUM ≠ 1 are dropped, but the spec says SEQ_NUM has no impact on local routing.
- **BUG‑2 (High):** Remote reassembly indexes fragment buffers by SEQ_NUM instead of FRAG_NUM, so multi-fragment remote packets never reassemble correctly.
- **BUG‑3 (Medium–High):** `drop_cnt` does not match the spec's "one count per dropped packet" rule.

## 4. Functional coverage model

Sampled on every observed input packet by `bird_coverage`.

| Coverpoint | Bins | Status |
|-----------|------|--------|
| `cp_traffic` | local, remote | Hit |
| `cp_len` | 0, 1, 2–15, 16–127, 128–254, 255 | Hit |
| `cp_frag` | 0, 1, 2–30, 31 | Hit |
| `cp_seq` | 0, 1, 2–30, 31 | Hit |
| `cp_reserved` | clean, violation | **violation = hole** |
| `cross traffic × len` | — | Partial |
| `cross traffic × frag` | — | Partial |

**Achieved functional coverage: 77.98%.** The main remaining hole is the
reserved-bit `violation` bin: producing it requires the driver to drive a `cfg`
with a reserved bit set (the transaction's `get_cfg()` currently always packs
reserved bits as 0). Recommended follow-up: add a small driver/test hook to
inject reserved-bit cfg words.
